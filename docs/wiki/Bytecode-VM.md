# バイトコードVMの設計

GuriのR7RS実装はスタック型のバイトコードVMを使用します。
#47で内部VMを実装し、#48でReaderの構文を命令列へコンパイルします。
現在の公開CLIとInterpreter.Evalの切替は移行作業に含まれ、内部VMの実装だけでは切り替わりません。

## 採用方式と処理の流れ

ユーザーはVM化を指定し、具体的な方式の選択を実装側へ委任しました。
コンパイル済みの命令をループで実行する方式を採用します。
レジスタ割当てを必要とせず、継続に保存する実行状態を列挙できるため、最初の実装はスタック型とします。
ASTを直接評価する方式や、Schemeの呼び出しごとにGoの関数を再帰呼び出しするCPSは採用しません。

```mermaid
flowchart LR
    R[Readerと位置付きdatum] --> E[束縛解決と構文展開]
    E --> C[コンパイラ]
    C --> B[命令列と定数と位置情報]
    B --> V[バイトコードVM]
```

#47時点では、テストで直接組み立てた命令列をVMで実行します。
#48でコア構文の[コンパイラ](https://github.com/0x6d61/guri/wiki/Core-Syntax)を接続しました。
マクロの展開は#49で追加します。
バイトコードはプロセス内部の表現であり、保存ファイルの形式、ABI、JIT、最適化パスは定義しません。
コードの実行中にReaderのNodeを参照する必要はありません。

## Codeと実行フレーム

`vm.NewCode(Spec)`は命令、定数、子関数、グローバル束縛のテーブルをコピーして所有します。
引数数、スロット数、命令種別、直接参照する添字と分岐先を検査します。
外部から供給されるバイトコードの検証器ではなく、コンパイラが生成する内部コード用です。
実行時にもオペランド不足や不正な外側スロットを診断します。

| 項目 | 内容 |
|---|---|
| Code | 名前、必須引数数、restの有無、ローカルスロット数、命令列、定数、子Code、グローバルCell |
| フレーム | Code、次の命令位置、環境、計算途中のオペランド |
| 環境 | 外側の環境への参照とCellの列 |
| VMの結果 | コレクション値とは別のscheme.Results。0個以上の値を保持 |
| ソース位置 | 各命令にファイル名・行・列。失敗時にvm.Errorが原因を包む |

クロージャはCodeと生成時の環境を保持します。
呼び出すたびに引数とローカル変数用の新しいCellを作ります。
外側のCellはクロージャ間で共有し、set!による更新を後からの呼び出しでも観測できます。
rest引数は新しいListにまとめます。
未初期化スロットの参照とsetはエラーにし、定義や再帰的束縛には専用の初期化命令を使います。

## 命令一覧

実装は`internal/vm/code.go`です。
AとBは整数オペランドで、分岐先はCode内の絶対命令位置です。

| 命令 | オペランド | 動作 |
|---|---|---|
| Const | A=定数番号 | 定数1個を結果にする |
| Push | なし | 結果が1個であることを確認し、オペランドへ積む |
| Pop | なし | 最後に積んだオペランドを取り出して結果にする。letrecの一時保存に使用 |
| Local | A=外側の深さ、B=スロット | Cellを読む。深さ0は現在の環境 |
| Global | A=Cell番号 | コンパイル時に解決したグローバルCellを読む |
| InitLocal / SetLocal | A=深さ、B=スロット | 初期化／既存束縛の更新。結果は未規定値 |
| InitGlobal / SetGlobal | A=Cell番号 | 初期化・再定義／既存束縛の更新。結果は未規定値 |
| MakeClosure | A=子Code番号 | 現在の環境を保持する手続きを生成 |
| Jump | A=分岐先 | 無条件に分岐 |
| JumpFalse | A=分岐先 | 単一の結果が#fの場合だけ分岐 |
| Call | A=引数数 | オペランドの手続きと引数を取り出して呼ぶ |
| TailCall | A=引数数 | 現在のフレームを除去してから呼ぶ |
| ReturnOp | なし | 現在のフレームを除去し、全結果を呼び出し元へ渡す |

コンパイラは手続き、引数の順で左から右へ評価して積みます。
この順序はR7RSが許容する逐次評価順の一つであり、移植可能なSchemeプログラムが依存できる順序を追加するものではありません。
Callの返り値は結果レジスタへ入り、式の用途に応じてPushやReturnOpで使用します。
単一値を必要とする箇所で0個や複数の値を受けた場合は診断します。
副作用だけを使う式は結果をそのまま上書きでき、最後の式と末尾呼び出しは複数値を維持します。

## 末尾呼び出しと継続

TailCallは呼び出し先へ移る前に現在のフレームを取り除きます。
呼び出し先がバイトコード、ネイティブ、継続のいずれでも同じルールを使います。
戻り先を追加しないため、末尾呼び出しの繰り返しでフレーム数は増えません。
非末尾の呼び出しの戻り先はGoスタックではなく、VMのフレーム列へ保持します。
不要になったフレームとオペランドの参照は消し、GoのGCで回収できるようにします。

ネイティブ呼び出しに渡すContextのCaptureは、現在の戻り先を手続き値として保存します。
継続には全フレーム、命令位置、計算途中のオペランド、動的状態を保存します。
保存時と再開時にフレームとオペランド列をコピーするため、同じ継続を何度でも呼び出せます。
CellやPairなどの値は共有し、継続の再開で過去の変数値へ巻き戻しません。
継続へ渡した全引数が、その戻り先へ渡す結果になります。

同じMachineでは、Runが終了した後も継続を再開できます。
異なるMachineに属する継続はErrContinuationOwnerで診断します。
これは独立した処理系インスタンス間の内部API境界であり、同一Scheme環境内の継続の有効期間を制限するものではありません。
標準のcall/ccとして言語に公開する作業は#51です。

## ネイティブ手続きの呼び出し契約

NativeFuncはGoの値を返す代わりにActionを返します。
`Return(values...)`は0個以上の結果を渡し、`Invoke(target, args, resume)`は別の手続きを呼びます。
resumeがnilなら、その呼び出しの結果を直接返します。
resumeがある場合は、VMが専用フレームを積み、呼び出し完了後にResumeへ結果を渡します。
ResumeもActionを返すため、反復的なmapやapplyからの再呼び出しをGoの再帰へ隠す必要はありません。

Resumeが保持する制御状態は不変にします。
例えば処理済みの添字を同じGo変数へ書き戻さず、次の状態を保持する別のResumeを作ります。
SchemeのCellへの副作用は共有したままにします。
これにより、Resumeの途中を含む継続も複数回再開できます。
NativeFuncとResumeからMachine.Runを再帰呼び出ししてはいけません。
同時・再入実行はサポートせず、同じMachineへの再入はErrReentrantで診断します。

## 動的状態と後続Issueへの契約

Dynamicは親とpayloadを持つ不変な連鎖で、Context.Dynamicから参照します。
Action.WithDynamicで次の実行状態へ渡し、継続はその参照を保存・復元します。
payload内に置くハンドラやパラメータの制御構造も不変として扱います。

#47ではdynamic-windのbefore/afterを実行しません。
#52では継続ジャンプ時の連鎖の差分を求め、脱出・再入のフックをActionとResume経由で実行してから目的のフレームへ移る処理を追加します。
単にDynamicを復元する現在の処理だけでdynamic-windが完成したとは扱いません。
#53ではハンドラ探索、raiseの転送、動的パラメータをこの動的状態と接続します。
複数値とscheme.Raisedの表現は共通値層を使い、これらの標準手続きは担当Issueで公開します。

## 検証と対応状況

- 10万回の末尾呼び出しでフレーム数が一定。
- ネイティブの再開を2万段、バイトコードを含む非末尾呼び出しを1万段実行。
- ネイティブの再開や途中の引数を含む継続を複数回実行。
- 継続の再開後もCellの変更を共有。
- restのList、0個と複数の返り値、動的状態の保存・復元を確認。
- 未初期化束縛、引数数、単一値の要求、位置付きエラー、キャンセルを確認。

R7RSの参照箇所は[§3.1、§3.5](https://standards.scheme.org/corrected-r7rs/r7rs-Z-H-5.html)、[§4.1](https://standards.scheme.org/corrected-r7rs/r7rs-Z-H-6.html)、[§6.10](https://standards.scheme.org/corrected-r7rs/r7rs-Z-H-8.html)です。
VMの単体検証を、未接続のCLIや標準手続き全体の準拠完了として扱いません。

## 内部APIの使用例

次の例はinternal/vm/example_test.goで出力を検証します。

```go
c, err := vm.NewCode(vm.Spec{
    Constants: []scheme.Value{scheme.NewInteger(42)},
    Instructions: []vm.Instruction{{Op: vm.Const}, {Op: vm.ReturnOp}},
})
if err != nil { panic(err) }
results, err := vm.New().Run(context.Background(), vm.Closure(c))
if err != nil { panic(err) }
value, err := results.Single()
if err != nil { panic(err) }
fmt.Println(value.(*scheme.Integer).String())
// 42
```
