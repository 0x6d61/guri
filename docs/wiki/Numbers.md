# Schemeの数値手続き

このページは内部の`core.NewCore`環境に登録した70の数値手続きを説明します。
#67で公開CLIと標準ライブラリの`import`へ接続しました。旧Go APIは削除しました。
`(scheme base)`、`(scheme inexact)`、`(scheme complex)`と`(scheme r5rs)`の数値束縛への割り当ては`docs/r7rs/exports.csv`で追跡します。
規格の参照先は[R7RS-small §6.2](https://standards.scheme.org/corrected-r7rs/r7rs-Z-H-8.html#TAG:__tex2page_sec_6.2)です。

## 表現と共通規則

任意精度整数、正確な有理数、binary64の不正確な実数、正確または不正確な複素数を扱います。
数値は不変であり、以下の手続きは引数を変更しません。
結果の数値を共有しても、変更による干渉はありません。
有理数は約分し、分母が1なら整数に正規化します。
虚部が正確なゼロなら実数へ正規化し、`-2.5+0i`は実数です。
不正確な虚部のゼロは符号を含めて保持し、`-2.5+0.0i`は実数ではありません。
複素数で片方の非ゼロ成分が不正確なら、両成分をbinary64として保持します。

以下で`z`は任意の数値、`x`は実数、`n`は整数値を表す実数、`k`は正確な整数を表します。
整数値のFloatである`3.0`は`n`として使えますが、`k`ではありません。
`...`は繰り返し、`[arg]`は省略可能な引数を表す説明用の記号です。

引数数の不一致はVMの引数数エラーになります。
型の不一致、正確なゼロ除算、定義できない操作、要求された表現で結果を返せない場合は、手続き名と引数を含むerror-objectを非継続可能に送出します。
`guard`または`with-exception-handler`で扱えます。
不正確な演算ではNaN、無限大、符号付きゼロを保持します。
VMの引数数エラーの自動送出は未接続であり、数値の型・演算エラーの送出と区別します。

## 述語と比較

| 手続き | 引数数・型 | 返り値 |
|---|---|---|
| `(number? obj)`、`(complex? obj)` | 1、任意 | 数値なら`#t` |
| `(real? obj)` | 1、任意 | 実数なら`#t` |
| `(rational? obj)` | 1、任意 | 有限の実数なら`#t` |
| `(integer? obj)` | 1、任意 | 有限の整数値なら`#t` |
| `(exact-integer? obj)` | 1、任意 | 正確な整数なら`#t` |
| `(exact? z)`、`(inexact? z)` | 1、数値 | 正確／不正確なら`#t` |
| `(zero? z)` | 1、数値 | 数値としてゼロなら`#t` |
| `(positive? x)`、`(negative? x)` | 1、実数 | 正／負なら`#t`。NaNでは`#f` |
| `(even? n)`、`(odd? n)` | 1、整数値 | 偶数／奇数なら`#t` |
| `(finite? z)`、`(infinite? z)`、`(nan? z)` | 1、数値 | 全成分が有限／いずれかが無限／いずれかがNaNなら`#t` |
| `(= z1 z2 z...)` | 2以上、数値 | 隣り合うすべての数値が等しければ`#t` |
| `(< x1 x2 x...)`、`(<= x1 x2 x...)`、`(> x1 x2 x...)`、`(>= x1 x2 x...)` | 2以上、実数 | 順序を満たせば`#t` |

型を問う最初の6述語は数値以外に`#f`を返します。
それ以外は対応しない型を渡すとエラーです。
混合比較ではFloatを正確な二進有理数として比較し、巨大整数をFloatへ丸めません。
NaNを含む等号・順序比較は`#f`です。
`=`は正確性とゼロの符号を区別しません。
マクロのdatum比較と`case`用の数値同値性は正確性と符号付きゼロを区別し、NaN同士は同値とする許容された選択を使います。
実数と虚部が不正確なゼロの複素数も区別します。

```scheme
(= 1 1.0)                            ; => #t
(> 9007199254740993 9007199254740992.0) ; => #t
(< 1/10 0.1)                         ; => #t
(real? -2.5+0i)                      ; => #t
(real? -2.5+0.0i)                    ; => #f
```

## 算術と整数

| 手続き | 引数数・型 | 返り値 |
|---|---|---|
| `(+ z...)`、`(* z...)` | 0以上、数値 | 和／積。空なら正確な0／1 |
| `(- z z...)`、`(/ z z...)` | 1以上、数値 | 左からの減算／除算。1引数なら符号反転／逆数 |
| `(abs x)` | 1、実数 | 絶対値 |
| `(max x x...)`、`(min x x...)` | 1以上、実数 | 最大／最小値。不正確な引数を含めば不正確な結果 |
| `(square z)` | 1、数値 | 二乗 |
| `(floor/ n1 n2)`、`(truncate/ n1 n2)` | 2、整数値 | 商と剰余の2値 |
| `(floor-quotient n1 n2)`、`(floor-remainder n1 n2)` | 2、整数値 | 負の無限大へ丸めた商／対応する剰余 |
| `(truncate-quotient n1 n2)`、`(truncate-remainder n1 n2)` | 2、整数値 | ゼロへ丸めた商／対応する剰余 |
| `(quotient n1 n2)`、`(remainder n1 n2)`、`(modulo n1 n2)` | 2、整数値 | r5rs用の別名。順にtruncate-quotient、truncate-remainder、floor-remainder |
| `(gcd n...)`、`(lcm n...)` | 0以上、整数値 | 非負の最大公約数／最小公倍数。空なら0／1 |
| `(numerator x)`、`(denominator x)` | 1、有限実数 | 約分した分子／正の分母。入力と同じ正確性 |
| `(floor x)`、`(ceiling x)`、`(truncate x)`、`(round x)` | 1、実数 | 下／上／ゼロ方向／最寄り偶数への整数丸め。入力と同じ正確性 |
| `(rationalize x tolerance)` | 2、実数 | 誤差区間に入る最も単純な有理数 |
| `(exact-integer-sqrt k)` | 1、非負の正確な整数 | `s² <= k < (s+1)²`の`s`と`k-s²`の2値 |

正確な引数だけの四則演算では、整数・有理数・複素数の正確性を保持します。
整数の固定幅オーバーフローはありません。
整数除算では除数ゼロをエラーにし、`n1 = q*n2+r`を満たします。
整数値への操作に非整数、無限大、NaNを渡すとエラーです。
ただし`floor`、`ceiling`、`truncate`、`round`は無限大とNaNをそのまま返します。
`rationalize`は許容誤差の絶対値を使い、両引数が正確なら正確な結果を返します。
NaNまたは無限の対象値はエラー、有限の対象値と無限の許容誤差は不正確なゼロになります。

```scheme
(+ 9223372036854775808 1) ; => 9223372036854775809
(/ 3 4 5)                ; => 3/20
(* 1+2i 3-4i)            ; => 11+2i
(round 5/2)              ; => 2
(rationalize 3/10 1/10)   ; => 1/3
(call-with-values (lambda () (floor/ -5 2))
  (lambda (q r) (= (+ (* q 2) r) -5))) ; => #t
```

## 正確性・数学関数・複素数

| 手続き | 引数数・型 | 返り値 |
|---|---|---|
| `(exact z)`、`(inexact z)` | 1、数値 | 正確／不正確な表現へ変換した数値 |
| `(inexact->exact z)`、`(exact->inexact z)` | 1、数値 | r5rs用のexact／inexactの別名 |
| `(sqrt z)` | 1、数値 | 主平方根。正確な平方根を整数・有理数成分で表せれば保持 |
| `(expt z1 z2)` | 2、数値 | べき乗。正確な底と正確な整数指数は正確に計算 |
| `(exp z)`、`(sin z)`、`(cos z)`、`(tan z)`、`(asin z)`、`(acos z)` | 1、数値 | 指数関数、三角関数、逆三角関数の主値 |
| `(log z [base])` | 1または2、数値 | 自然対数または指定した底の対数の主値 |
| `(atan z)` | 1、数値 | 逆正接の主値 |
| `(atan y x)` | 2、実数 | 符号と象限を保持した偏角 |
| `(make-rectangular x y)` | 2、実数 | 実部x、虚部yの数値 |
| `(make-polar radius angle)` | 2、実数 | 絶対値と偏角から作る数値 |
| `(real-part z)`、`(imag-part z)` | 1、数値 | 実部／虚部の実数 |
| `(magnitude z)`、`(angle z)` | 1、数値 | 絶対値／偏角の実数 |

`exact`は有限Floatの二進値を正確な有理数へ変換し、無限大とNaNではエラーになります。
`inexact`はbinary64へ丸めます。
数学関数は正確な0や1などの結果を保持する場合を除き、binary64を使います。
`make-polar`は正確な半径ゼロまたは正確な角度ゼロを両引数が正確な場合に保持し、一般の角度は不正確な複素数にします。
`sqrt`は結果の実部がゼロなら虚部を非負にします。
正確なゼロの`log`と`angle`、両引数が正確なゼロの`atan`、ゼロの底で指数の実部が正でない非ゼロ指数の`expt`はエラーです。

```scheme
(exact 0.5)         ; => 1/2
(sqrt -1)           ; => +i
(magnitude 3+4i)    ; => 5
(expt 2 -70)        ; => 1/1180591620717411303424
```

## 数値と文字列

| 手続き | 引数数・型 | 返り値 |
|---|---|---|
| `(number->string z [radix])` | 1または2、数値と正確な整数 | 新しいString |
| `(string->number string [radix])` | 1または2、Stringと正確な整数 | 数値、または変換できなければ`#f` |

基数は2、8、10、16で、既定値は10です。
Stringを変更せず、number->stringの結果は元のStringと可変領域を共有しません。
対応しない基数または引数型はエラーです。
文字列内の明示的な基数指定が省略引数の基数より優先します。
Readerと同じ`ParseNumberRadix`で文字列全体を変換し、前後の空白や余分なトークンも許しません。
不正な数値の内容を`#f`にすることと、引数型や基数のエラーを区別します。

number->stringは明示的な基数prefixを付けず、同じ基数のstring->numberで数値同値な値へ戻せる表現を返します。
10進のFloatは小数点を付け、他の基数では必要に応じて`#i`と正確な二進有理数の表記を使います。
負のゼロと複素数の不正確な虚部ゼロも保持します。
正確な一般極形式を有理数成分で表せない場合の制限は[Reader](https://github.com/0x6d61/guri/wiki/R7RS-Reader)を参照してください。

```scheme
(= (string->number (number->string 3/7 16) 16) 3/7) ; => #t
(string->number "#x10" 2)                          ; => 16
(string->number "bad")                            ; => #f
(guard (e (else #t)) (/ 1 0) #f)                  ; => #t
```

## 検証と残る接続

`internal/number`は全登録名の実行と引数数、正確演算、丸め、比較、複素数、非有限値と書式往復を外部から検証します。
`internal/core`は実際の数値手続きを使い、継続・末尾反復・複数値・例外との組み合わせを検証します。
このページのscheme例は`TestNumericWikiExamples`で独立した内部環境を使って実行します。
この単体検証とは別に、#67で公開CLIへ接続して17件と62件を実測し、成功しました。16標準ライブラリをimportできます。
