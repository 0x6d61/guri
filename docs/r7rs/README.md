内部実装の検証を、公開CLIや言語全体の準拠判定として扱いません。
`id`は節番号に基づく安定した識別子、`source`は該当節、`issue`は主担当、`acceptance`は節単位の受入条件です。
`baseline`はmasterの986a428を読んだ結果であり、`status`と`evidence`は規格に対する検証状態です。
章の見出しや参考意味論も索引として含むので、96という件数を必須機能数や準拠率として使いません。

各実装PRで条件を個別化した下位IDを追加し、必須、任意、実装依存、未規定、エラー条件を分類します。
初回台帳は節単位の受入条件までを整理したもので、すべての規格文を個別化したものではありません。
追加した下位IDは、親の節番号と出典へ戻れるようにします。

## exports.csv

補正済みAppendix Aの各一覧から、16ライブラリの557公開束縛を転記しています。
キーは`library`と`identifier`の組です。
手続きだけでなく構文と補助キーワードも含みます。
`section`は動作の参照先、`issue`は主担当です。
初期の節参照が関連機能の節にまとまっている場合は、実装時に個別の構文の節も確認します。

`requirement`はbaseとそれ以外を区別します。
base以外はライブラリを採用した場合に公開一式を満たす必要があります。
r5rsの一覧は任意ライブラリを含む元の公開一覧で、採用範囲が決定したら§Aの条件に従って調整します。
存在しない束縛をダミー関数で埋めて提供済みにはしません。

`status`の「差分あり」は同名の独自実装があることを示し、標準の動作を満たす意味ではありません。
`baseline_evidence`は現状を確認したファイル、`test_evidence`は標準の振る舞いを確かめるテストへの参照です。
空欄の証拠を検証済みとして扱いません。
現状のどの標準ライブラリもimportできない点は、すべての束縛に共通する不足です。

## 更新と検査

CSVはUTF-8で保存し、カンマや引用符を含む欄はCSVの規則でエスケープします。
独自仕様を残すために規格由来の行を削除しません。
規格資料を更新するときはURL、版、ハッシュ、一覧差分と影響する要求IDをPRへ記載します。
`r7rscheck`はケースの節番号をこの台帳へ照合し、要求IDごとの結果をJSONに記録します。
結果から台帳を自動的に検証済みへ変更することはありません。
